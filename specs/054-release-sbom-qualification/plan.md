# Plan: Spec 054 Release SBOM Qualification

## Architecture
New module `medscale-core::release_sbom` (pure logic, no I/O beyond string IO):
- `ReleaseSbomInput`: source_sha, tree_sha, cargo_lock_sha256, build_env
  (os, os_version, target_triple, rustc, cargo), workspace_packages[],
  rust_deps[] (name, version, license, purl), native_deps[] (name, classifier,
  detail), artifacts[] (name, sha256), pack_assets[] (name, kind, rights_note).
- `generate_release_sbom(input) -> String` (deterministic JSON, sorted keys,
  sorted components, fixed timestamp `1970-01-01T00:00:00Z`).
- `verify_release_sbom(doc, expected) -> VerificationReport` with explicit
  failure codes: `parse_error`, `missing_property`, `digest_mismatch`,
  `missing_workspace_package`, `native_unclassified`, `missing_artifact`,
  `license_fabrication` (reserved: generator never fabricates; verifier rejects
  empty license objects).

Doctor wiring: add `release_sbom_qualified: bool` to
`ReleaseQualificationDoctorStatus`; `prep_ready_base()` sets it true and
removes `release_sbom_native_model_assets` from the missing list; core doctor
computes it by locating the committed SBOM document
(`evidence/054-release-sbom/SBOM.cdx.json`) and verifying digests against live
`HEAD`/`HEAD^{tree}`/`Cargo.lock`. `release_ready` stays false.

Generator binary path: deterministic doc is (re)generated by a test helper and
committed; a PowerShell script `scripts/generate-release-sbom.ps1` re-generates
it from `cargo metadata` + live git state for operators.

## Test strategy
Positive: generate from fixture input → verify ok; committed doc verifies
against live checkout at test time (via env-provided SHAs or git).
Negatives: tampered component; stale lock digest; missing workspace package;
unclassified native dep; missing artifact; missing required property; invalid
JSON. Doctor test: qualified=true, release_ready=false.
