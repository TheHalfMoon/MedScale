# Spec 073 — Final UI Polish

Status: CLOSED_CANONICAL

## Founder promotion

The founder explicitly requested a final UI/brand pass, subsequently expanded the identity scope to Desktop, Web, and CLI, and then explicitly authorized refinement of the approved `M` geometry into a distinctive MedScale signature mark. This fresh promotion reopens repository implementation for a bounded cross-surface product-identity pass: native Desktop implementation, CLI human-output identity, and a Web reference contract/prototype only because no production Web app exists in this repository.

## Goal

Finish the MedScale product identity so Desktop, CLI, and future Web surfaces share one production-grade visual language while preserving every established authority, privacy, evidence, accessibility, and claim boundary.

## Acceptance criteria

1. Refine the shared visual system, navigation, top bar, page header, cards, actions, tabs, metrics, and status treatment without adding backend authority.
2. Finish the Home workspace hierarchy, AI inspection surface, clinical flow, and review queue with consistent spacing and interaction affordances.
3. Apply the shared polish across Patients, Insights, Models, Evidence, Workflows, governance, and utility routes through reusable components/tokens rather than one-off styling drift.
4. Preserve keyboard focus, accessible labels/actions, minimum window support, local-first status, evidence-first copy, release non-claims, and MESC project separation.
5. Capture rendered before/after evidence on the authorized macOS host.
6. Define one canonical brand system: founder-approved monochrome circular signature M mark with the MedScale Shelf, adaptive light/dark tokens, embedded typography, icon grammar, spacing/radius rules, and copy principles.
7. Apply the identity to Desktop and safe human-facing CLI output; add a Web reference implementation/design contract without claiming a production Web surface.
8. Pass focused product/UI regressions, Desktop/CLI tests, formatting, Clippy, Rust 1.88, workspace qualification, exact-range review, exact-head required CI, protected merge, and post-main verification.

## Non-goals

No new clinical authority, provider integration, network authority, model claim, release-readiness claim, production Web runtime, mobile implementation, MESC work, or backend feature is authorized by this spec.
