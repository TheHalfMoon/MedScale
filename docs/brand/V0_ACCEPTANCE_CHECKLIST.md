# MedScale V0 Acceptance Checklist

**Status:** FOUNDER_APPROVED_HANDOFF — Spec 093

A V0 result is acceptable only if all applicable items below are true.

## Identity

- Uses the canonical ScaleFold M without alternate-logo exploration.
- Uses canonical MedScale tokens rather than an invented palette.
- Uses ScaleFold Language as a generative system, not merely a logo placement.
- Includes supergraphics/pattern rhythm that still feels MedScale with the full logo hidden.
- Keeps gradient as identity/focal treatment, not semantic state.
- Preserves Instrument Sans, Source Serif 4, and monospace roles.
- Any ScaleFold Display treatment is rare, legible, and derived from Instrument Sans rather than introducing a competing font.
- Light and dark feel intentionally designed, not mechanically inverted.

## Product craft

- Global rail, adaptive sidebar, workspace canvas, and optional inspector are coherent.
- Work surfaces use hierarchy and whitespace before nested cards.
- Primary task is obvious within five seconds of scanning a screen.
- Dense pages remain readable at 1440×900 and 1280 widths.
- Narrow layouts collapse secondary navigation before essential work.

## Components

- Shared primitives are reused consistently.
- Hover, focus, active, disabled, loading, empty, and error states are represented where relevant.
- Status is never communicated by color alone.
- Icons follow the original MedScale line grammar and are not copied from competitors.
- Controls and panels use canonical radius tokens.

## Trust and truth

- Synthetic/demo data is clearly synthetic.
- Future Research OS V2 features are not presented as already implemented.
- Model/runtime/provenance state remains explicit.
- AI output is not styled as clinical authority.
- No invented superiority, readiness, outcome, security, compliance, or benchmark claims.
- Evidence, source, uncertainty, and review state remain visually close to consequential output.

## Accessibility

- Every control has a visible keyboard focus state.
- Icon-only controls have accessible names and tooltips where useful.
- Text contrast is sufficient in both themes.
- Long labels and localized strings do not break layout.
- Reduced-motion behavior exists for non-essential transitions.
- Interactive target size is appropriate for desktop and touch-capable narrow layouts.

## Distinctiveness

Reject the result if it looks like:
- a generic shadcn dashboard;
- a clone of JetBrains, Abridge, Cohere, Linear, Vercel, or another reference;
- a neon AI control panel;
- a hospital/EHR skin built from medical clichés;
- a wall of gradient cards or colored icon tiles;
- Abridge-style waveform lettering or bridge/masonry mimicry;
- repeated miniature M logos used as decoration.

The final system must remain recognizably MedScale even when the logo is temporarily hidden.
