## Authorized scope

Spec 078 may implement only the minimum governed, local-first fleet/compare
layer described in `specs/078-model-fleet-compare/spec.md`:

- `AgentLane`/`LanePolicy`/`LaneTransform`: an explicit, bounded execution
  lane wrapping an admitted `AgentIdentity`/`AgentCapabilityManifest`/
  `ContextManifest` (all Spec 077 primitives, reused as-is) plus lane-scoped
  policy (which context/tool/data/network grants this lane's run may use —
  never wider than what Spec 077's own `AgentRun` already enforces per
  identity/context, and never unioned across lanes);
- `FleetRun`/`FleetRunState`/`LaneRunRef`: a persisted parent record binding
  two or more lane runs (each a real Spec 077 `AgentRun`) to one comparison
  task, with an explicit state machine tracking per-lane completion and
  overall fleet status, including partial-failure states;
- `ComparisonRequest`/`ComparisonObservation`/`ComparisonReport`: a
  structural, evidence-preserving comparison over two or more completed (or
  explicitly partially-failed) lane runs' `AgentProposal`/`RunReceipt`
  output — agreement/disagreement facts, contradiction candidates, evidence/
  citation overlap, unsupported-claim candidates, abstention, schema
  validity, and resource/runtime facts — with **no default quality score
  and no declared winner** anywhere in the output shape or its rendering;
- reuse of Spec 077's `AgentIdentity`, `AgentCapabilityManifest`,
  `ContextManifest`, `AgentRun`/`AgentRunState`/`AgentTurn`,
  `ToolInvocation`/`ToolReceipt`, `RunReceipt`, `AgentProposal` exactly as
  frozen — **no modification to any Spec 077 contract, storage table, or
  Core authority function**; `FleetRun` is a new, additive layer that
  *drives* multiple independent Spec 077 runs, never a fork of Spec 077's
  own run machinery;
- CLI vertical slice and native Slint Desktop fleet/compare panel (fleet
  create/detail, lane status, comparison report view), both backed
  exclusively by Core;
- encrypted local persistence and migration (storage schema v6 -> v7,
  additive only);
- migration, recovery, compatibility, security, and exact-head evidence
  required for closure.

### Lane-plurality scope decision (frozen at promotion; binding on T078-01)

`RESEARCH_OS_V2_SPEC_IMPLEMENTATION_CONTRACTS.md`'s closure gate for 078
requires "at least two distinct admitted lanes run the same task." This
repository currently has **exactly one real, qualified local model
runtime/Pack with genuine inference capability**
(`OnnxTokenClassifierRuntime` against the Spec 069 fixture Pack
`pack-tiny-token-classifier-v0`; `FixtureRuntime`/`pack-fixture-ner-v0` is a
deliberate stub with no real inference, per Spec 008's own design). No
second real admitted model Pack exists on this base.

Verified against the roadmap text itself
(`RESEARCH_OS_EXECUTION_ROADMAP.md` line 223, "same-task **and**
role-specialized lane semantics") and against the contracts list
(`AgentLane`, `LanePolicy` — a *lane-scoped policy* object distinct from
the Pack it runs, section "Contracts" of the 078 entry): "distinct admitted
lane" is a property of the **`AgentLane`** (its policy — bound
`AgentIdentity`, `ContextManifest`, granted tool/data/network scope, and an
explicit role label), not a property of requiring two structurally
different `PackRuntimeAdapter` implementations to exist. Two `AgentLane`s
that both bind an `AgentIdentity` registered against the *same* admitted
Pack, but carry genuinely distinct lane policy (different `ContextManifest`
selections and/or different role-specialized prompts/tool grants), are two
distinct admitted lanes under this reading — "same-task" lane semantics is
explicitly named as one of the two required semantics, and the comparison
machinery's job (agreement/disagreement, contradiction, unsupported-claim
detection) must be honest and meaningful regardless of whether the
underlying model happens to be identical across lanes.

This is recorded here as an explicit, disclosed scope decision, not a
silent narrowing:

1. Spec 078's `FleetRun` and comparison machinery MUST NOT assume or
   require model diversity across lanes. Comparison semantics must be
   provably correct (agreement/disagreement, contradiction candidates,
   evidence overlap, abstention, schema validity) even when every
   participating lane is bound to the identical admitted Pack.
2. The closure-gate synthetic fixture proving "at least two distinct
   admitted lanes run the same task" uses **two `AgentLane`s bound to the
   same currently-admitted Pack** (`pack-tiny-token-classifier-v0`, via
   `OnnxTokenClassifierRuntime`) but with deliberately different lane
   policy — distinct `ContextManifest` artifact selections and/or distinct
   role-specialized prompts — so that the resulting `AgentProposal`s are
   genuinely independently produced, not a single run's output duplicated.
   This is a real "run the same task, two lanes" proof, not a fabricated
   one: each lane executes its own real `AgentRun` through Spec 077's own
   machinery, start to finish.
3. If and when a second genuinely distinct admitted local model Pack exists
   in this repository (a later spec or a separate Pack-admission action —
   out of this spec's authority to create), the same `AgentLane`/`FleetRun`
   contracts must support binding lanes to different Packs without any
   contract change; this is a design constraint on T078-01's freeze, not
   deferred work.
4. This decision does not weaken the closure gate's actual intent (no
   permission union across lanes, partial failure explicit, no default
   winner) — it resolves only the narrow question of what "distinct
   admitted lane" requires when the repository's real model inventory is
   the limiting factor, exactly as `plan.md`'s stop-condition discipline
   requires resolving such a gap explicitly rather than silently building
   an unauthorized second inference engine to manufacture diversity.

## Mandatory architecture constraints

1. Reuse Spec 077's `AgentIdentity`, `AgentCapabilityManifest`,
   `ContextManifest`, `AgentRun`/`AgentRunState`/`AgentTurn`,
   `ToolInvocation`/`ToolReceipt`, `RunReceipt`, `AgentProposal` exactly as
   frozen. `FleetRun` orchestrates multiple independent `AgentRun`s; it
   never re-implements run execution, tool dispatch, or proposal
   submission.
2. `AgentLane` is a policy wrapper, not a new execution engine: each lane's
   actual model execution happens through the same Spec 077
   `execute_agent_run` path, against the lane's own bound `AgentIdentity`/
   `ContextManifest`. No lane executes model inference through any code
   path other than the one Spec 077 already qualifies.
3. No permission union across lanes: each lane resolves its own context/
   tool/data/network grants independently; a `FleetRun` object never widens
   any lane's grants beyond what that lane's own `AgentCapabilityManifest`/
   `ContextManifest` already allow, and never lets one lane's run read
   another lane's context or tool results while either is in flight.
4. Comparison is observation, not judgment: `ComparisonReport` records
   agreement/disagreement, contradiction candidates, evidence/citation
   overlap, unsupported-claim candidates, abstention, schema validity, and
   resource/runtime facts. No field or derived value ranks lanes, assigns a
   quality score, or declares a winner. This is proven by contract shape
   (no such field exists) and by review, not merely by convention.
5. Partial lane failure is explicit: a `FleetRun` where one lane fails or is
   cancelled while others complete is a distinct, inspectable
   `FleetRunState`, never silently presented as a full comparison or
   silently excluded without record.
6. Comparison privacy inheritance: **amended at T078-01** (see
   `specs/078-model-fleet-compare/contracts.md` section 4's reconciliation
   note). Live inspection found no data-classification/privacy-sensitivity
   primitive anywhere in this repository (`RealmId`/`AuthorityScopeId` are
   authorization-scope identifiers, not a sensitivity taxonomy; `DataClass`
   is Spec 079's own future contract). Building one here to satisfy this
   constraint would itself be the out-of-scope "new data-class/egress
   policy engine" section "Explicitly not authorized" forbids. The
   constraint is therefore narrowed to: `ComparisonReport` carries **no**
   classification field in this spec's v1 frozen shape, rather than a
   fabricated or misapplied one; a future spec adds it back additively once
   a real classification primitive exists to inherit from.
7. CLI and Desktop must use the same Core command/query semantics. No
   direct storage/model-runtime access from UI.
8. Local/offline operation is mandatory: with network egress disabled,
   every 078 workflow remains fully useful. Spec 078 opens no network
   connection to any external model/browser provider and requires none —
   every lane in this spec's scope is local-process only.
9. Migration must preserve all pre-078 workflows and object identities (no
   existing object ID rewrite); Spec 077 tables/rows are never modified by
   078 migration.
10. Unknown/unavailable/stale/partial/cancelled/failed states stay
    distinct; missing input is not zero; partial comparison output is never
    silently presented as complete.
11. No later Research OS unit may be started merely because its planning
    document exists.

## Frozen acceptance requirements

Spec 078 can close only when all of the following are proven on the exact
reviewed head:

1. An `AgentLane` can be created bound to an existing, admitted
   `AgentIdentity` and `ContextManifest`, with explicit lane policy, and
   this survives close/reopen.
2. A `FleetRun` binding at least two distinct `AgentLane`s can execute the
   same task (same prompt intent) end to end, each lane producing its own
   independent, real `AgentRun`/`AgentProposal`/`RunReceipt` through Spec
   077's existing, unmodified machinery — zero network.
3. A `ComparisonReport` over the completed `FleetRun`'s lane outputs
   records agreement/disagreement, contradiction candidates, evidence/
   citation overlap, unsupported-claim candidates, abstention, schema
   validity, and resource/runtime facts, with no quality score or winner
   field anywhere in its shape.
4. A `FleetRun` where one lane fails or is cancelled while another
   completes reaches an explicit partial-failure `FleetRunState`; the
   surviving lane's output remains inspectable and is never silently
   presented as a full comparison.
5. No lane's run can read another lane's context, tools, or in-flight
   results — proven structurally, not merely by absence of a test failure.
6. No code path exists from `FleetRun`/`ComparisonReport` output into
   `ClinicalAssertion` creation, `PromoteProposal`, `TransitionEffect`, any
   controlled-action capability, or any automatic "resolve the
   disagreement" mechanism.
7. No Spec 077 contract, storage table, or Core authority function is
   modified by this spec; Spec 077's own test suite remains green
   unmodified (aside from mechanical fixes forward for storage schema
   version constants that were already an established pattern in Spec
   074/075/076/077's own history).
8. Pre-078 vaults (including populated 074/075/076/077 vaults) migrate
   (v6 -> v7), reopen, and recover from backup.
9. No alternate authority/storage/network path exists (dependency-direction
   gate holds).
10. Every 078 workflow remains usable with network disabled.
11. No real-PHI authorization is implied; fixtures are synthetic/permitted
    non-PHI.
12. Exact-head required CI and post-main verification pass.
